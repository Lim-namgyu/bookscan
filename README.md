# 북스캔 (vFlat형 책 스캔 앱)

책을 찍으면 **휜 페이지를 반듯하게 펴고, 페이지를 누른 손가락을 지우고, 그림자를 없애** 깨끗한 스캔본으로 만드는 안드로이드 앱입니다. 모든 처리는 **폰 안에서** 이뤄지고 서버가 필요 없습니다.

```
bookscan/
├─ android/BookScan/   ← 안드로이드 스튜디오 프로젝트 (Kotlin + Jetpack Compose)
└─ engine/             ← 같은 보정 엔진의 파이썬 버전 (PC에서 사진으로 품질 시험·수치 조정용)
```

## 빌드 방법

1. Android Studio(Ladybug 2024.2 이상)에서 **Open → `android/BookScan` 폴더** 선택
2. Gradle Sync가 끝나면 휴대폰을 USB로 연결하고 **Run ▶**
   - 64비트 ARM 휴대폰 기준으로 빌드됩니다. 에뮬레이터에서 돌리려면 `app/build.gradle.kts`의 `abiFilters`에 `"x86_64"`를 추가하세요.
   - 최소 안드로이드 10(API 29)
3. 처음 실행하면 카메라 권한을 허용하세요.

> GitHub에 올리면(main 브랜치) **GitHub Actions가 자동으로 APK를 빌드**해 Releases에 올립니다(`.github/workflows/build-apk.yml`). 휴대폰에서 Releases의 `BookScan-번호.apk`를 받아 바로 설치하면 됩니다.
>
> 엔진 코드가 바뀌면 **엔진 검사**(`.github/workflows/engine-test.yml`)도 돕니다: 앱에 들어가는 Kotlin 엔진을 PC(JVM)에서 그대로 실행해(`android/enginetest`) `engine/testdata/` 사진을 처리하고 파이썬 기준 구현 결과와 비교합니다. 두 결과 이미지는 Actions 의 Artifacts(`engine-outputs`)에서 내려받아 볼 수 있습니다.

## 기능

| 화면 | 기능 |
|---|---|
| 촬영 | 자동/한 쪽/양면 선택, 컬러/회색/흑백, 손가락 제거 on/off, 조명(플래시), 탭해서 초점. **촬영 안내**: 책이 화면에 다 들어왔는지·크기·위치, 폰 기울기, 밝기·반사, 흔들림, 초점을 실시간으로 판단해 안내 문구와 초록 테두리로 "지금 찍어도 좋다"를 표시. **자동 촬영**은 그 상태가 잠시 유지되고 장면이 바뀌었을 때(페이지를 넘겼을 때)만 찍음. 폰을 가로로 들고 찍어도 사진이 눕지 않음 |
| 목록 | 찍은 페이지 격자 보기, **PDF로 저장·공유**(다운로드/BookScan 폴더에도 저장), 사진 앱에 JPG 저장 |
| 페이지 | 색상 모드·손가락 제거 다시 적용, 90도 회전, **수동 지우개**(남은 얼룩을 문질러 지우기), 삭제 |

## 보정 순서 (엔진)

0. **책 찾기**: U²-Net-p 모델(ONNX, 2.3MB)로 사진에서 책(펼친 페이지 전체)을 바닥·책상과 분리. 책이 작게 찍혀도 책 부분만 잘라서 처리
1. **방향 맞춤**: 폰을 세로로 든 채 펼친 책을 찍어 글이 옆으로 누우면 바로 세움. 글줄을 수평으로 맞춘 뒤 문장부호 위치와 줄 시작 정렬로 위아래를 판단
2. **양면 분리**: 책 윤곽이 가로로 길면 양면. 책 바깥 두 변의 가운데 선 근처에서, 두 페이지 글 사이 빈 띠 + 접힌 곳의 옅은 그림자를 찾아 좌/우로 나눔(책이 기울어 있어도 비스듬한 직선으로)
3. **곡면 펴기**: 페이지 바깥을 가린 뒤 UVDoc 딥러닝 모델(ONNX, 16MB)로 휜 페이지를 평평하게 + 실제 페이지 비율 복원. 휘어 기울어진 부분이 사진에 짧게 찍혀 글자가 세로로 길쭉해지는 것은 지도의 국소 배율로 바로잡음
4. **글줄 반듯하게**: 모델이 남긴 기울기·휨을 글자 자체를 기준으로 마저 바로잡음
   - 글줄을 하나하나 찾아 곡선으로 따라간 뒤, 모든 글줄이 수평 직선이 되도록 세로로 보정
   - 줄 시작(왼쪽 여백)·끝(오른쪽 여백)이 세로 직선이 되도록 가로로 보정. 여백이 들쭉날쭉한 글(표·시)은 글자 세로획 각도로 판단
   - 페이지를 통째로 돌리지 않아 글자가 이탤릭처럼 눕지 않음. 밑줄·표 테두리·머리글 장식선 같은 가로 괘선(휘어 있어도)도 기준으로 씀
   - 옆으로 누운 표(가로로 인쇄된 쪽)는 그 방향 그대로 처리
   - 페이지 끝이 카메라 쪽으로 말려 모델이 덜 편 곳은 글자가 위아래로 늘어나 있음(아래쪽 글줄이 위쪽보다 10% 넘게 커지기도). 글줄마다 글자 몸통 띠 두께를 재서 세로 배율을 고르게 맞춤 — 본문처럼 글자 크기가 고른 쪽에서만(제목·보기 글자 크기가 섞인 쪽은 그대로 둠)
   - 곡면 펴기와 합쳐 원본 사진에서 **한 번만** 다시 그리므로 글자가 흐려지지 않음
5. **책 바깥 지우기**: 책 영역을 같은 지도로 옮겨 바닥·책상이 남은 가장자리는 잘라내거나 종이색으로 메움. 책 옆면(종이 단면 줄무늬)도 잘라냄
6. **손가락 제거**: 종이보다 붉은 피부색 덩어리 중 페이지 가장자리에서 안쪽으로 파고든 것을 찾아, 주변 종이색으로 메우고 옆 그림자까지 밝힘. 양면일 때 접힌 선 쪽은 검사하지 않고, 가장자리를 따라 가늘고 길게 붙은 띠(누렇게 바랜 책 옆면)는 손가락으로 보지 않음
7. **화질 보정**: 종이 배경(조명·그림자)을 추정해 나눠서 바탕을 흰색으로(어두운 곳은 밝히며 커지는 잡음을 배율에 비례해 누름). 글자는 이진화하듯 깎지 않고 가장자리의 부드러운 회색까지 살린 채 진하게(획이 끊기거나 얇아지지 않게). 흰색 기준을 자리마다 달리해, 진한 글자·긴 선·색 있는 곳 근처는 그대로 두고 그 밖의 뒷면 비침은 지움. 색(지도·색 상자)은 누런 종이 색을 빼고 살림. 가장자리에 남은 선·잔무늬 찌꺼기(상자 테두리는 남김) 정리

처리 해상도는 긴 변 3000px(책 한 쪽 기준 약 300dpi 이상), 글줄 분석은 긴 변 1600px에서 합니다.

### 기울어진 책 테스트 결과

책을 7~20° 돌려 놓고 찍은 사진, 원근이 들어간 사진, 원래 사진 등 10쪽으로 잰 값입니다(`engine/textlines.py`의 측정 함수, 폭 1000px 기준).

| 항목 | 글줄 반듯하게 전 | 후 |
|---|---|---|
| 글줄 기울기 (중앙값) | 0.2 ~ 2.0° | 0.02 ~ 0.08° |
| 글줄 휨 (중앙값) | 2.1 ~ 7.8px | 0.6 ~ 1.2px |
| 왼쪽 여백 흔들림 | 8 ~ 15px | 1 ~ 5px |
| 글자 세로획 기울기 | 최대 1.9° | ±0.5° 이내 (측정 오차 수준) |

## 실사용 전 조정할 곳

| 무엇 | 파일 · 위치 | 설명 |
|---|---|---|
| 촬영 안내·자동 촬영 기준 | `camera/CaptureReadiness.kt` 맨 아래 상수 | `SHARP_T`(초점), `STILL_T`(흔들림), `DARK_T`/`CLIP_T`(밝기), `TILT_MAX`(기울기), `AREA_MIN`/`TOUCH_T`/`CENTER_T`(책 크기·잘림·위치), `READY_FRAMES`(자동 촬영까지 유지 시간) |
| 손가락 색 기준 | `engine/BookScanEngine.kt` → `fingerMask()` | 피부 판정(붉은기 `> 8`, 색상각 `25~60°`)과 크기·위치 조건 |
| 처리 해상도 | `BookScanEngine.MAX_SIDE` | 크게 하면 선명하지만 느려지고 메모리를 더 씀 |
| 글자 진하기·배경 | `BookScanEngine` 의 `TONE_GAMMA`, `S_MIX`, `WHITE_BG`, `WHITE_TEXT` | 감마를 올리면 글자가 진해짐. `WHITE_BG`를 낮추면 뒷면 비침이 더 지워지지만 옅은 인쇄(회색 글씨)도 옅어짐. `LINE_DARK`/`LINE_DARK_FRAC`: 옅은 긴 선을 인쇄된 선으로 볼 기준 |
| 색 보존 | `CHROMA_KEEP`, `COLOR_SAT` | 종이 색을 뺀 채도가 `CHROMA_KEEP` 이상인 곳(색 상자·그림·색 글씨)만 색을 남기고 `COLOR_SAT` 배로 진하게 |
| 글줄 분석 해상도 | `BookScanEngine.ANALYSIS_SIDE` | 글자가 아주 작은 책(사전 등)이면 2000 정도로 올리면 글줄을 더 잘 찾음 |
| 세로 배율 보정 | `Straightener` 의 `SCALE_*` | `SCALE_RESID_MAX`(글자 높이 흩어짐 허용치)를 올리면 글자 크기가 섞인 쪽에도 적용되지만 잘못 줄일 위험이 커짐. `SCALE_CLAMP_*`: 배율 한계 |

**가로 촬영 방향**: 폰을 세우거나 기울인 방향으로 사진 방향을 정합니다. 책 위에서 폰을 거의 수평으로 들면 방향을 알 수 없어 마지막으로 기울였던 방향을 따르니, 양면을 가로로 찍을 때는 폰을 가로로 살짝 세웠다가 내려 찍으세요.

**Play 스토어에 올릴 계획이라면** 빌드한 APK를 Android Studio의 APK Analyzer로 열어 16KB 페이지 정렬 경고가 있는지 확인하세요. 경고가 뜨면 `app/build.gradle.kts`의 OpenCV·ONNX Runtime 버전을 최신으로 올리면 됩니다.

**손가락 제거는 합성 손가락 사진으로만 검증했습니다.** 실제 손가락 사진에서 잘 안 지워지거나 엉뚱한 곳(누렇게 바랜 책 가장자리 등)이 지워지면, 그 사진을 `engine/`에서 아래처럼 돌려보고 수치를 맞춘 뒤 같은 값을 Kotlin 쪽에 옮기면 됩니다.

```bash
cd engine
pip install opencv-python onnxruntime numpy
python bookscan.py 내사진.jpg --out 결과   # 결과 폴더에 페이지별 JPG + 손가락 마스크 PNG
python bookscan.py 내사진.jpg --mode bw --layout double --out 결과
```

## 엔진 폴더 파일

- `bookscan.py` — 파이썬 기준 구현 (앱과 같은 알고리즘). `--no-straighten` 으로 글줄 반듯하게 단계를 끄고 비교할 수 있음
- `straighten.py` — 글줄 반듯하게 (앱의 `engine/Straightener.kt` 와 같은 알고리즘)
- `testdata/` — 검사용 사진, `compare_outputs.py` — 파이썬 결과와 앱 엔진 결과 비교, `measure_outputs.py` — 결과 품질 수치표(글줄 기울기·휨·줄 간격·글자 비율)
- `textlines.py` — 글줄·괘선 찾기, 반듯함 측정 함수
- `kt_mirror.py` — 안드로이드 코드의 OpenCV 호출을 그대로 옮긴 검증용 버전
- `build_uvdoc_onnx.py` — UVDoc 원본 가중치(PyTorch 체크포인트)를 PyTorch 없이 ONNX로 변환
- `compact_onnx.py` — 가중치를 float16으로 저장해 모델 용량을 절반(16MB)으로
- `orient.py` — 사진 방향 자동 맞춤
- `region.py` — 책 영역 찾기(U²-Net-p)
- 모델 파일은 앱 폴더의 `android/BookScan/app/src/main/assets/`(`uvdoc.onnx`, `u2netp.onnx`)를 같이 씁니다
